# 原生 C/C++ 调度池化对照实验

日期：2026-09-06。实验目录：`performance-native-pool-final-001`。

本实验将最大池化前向和反向 kernel 放入原生 CUDA 调度 DLL。Python 层只负责 CuPy 数组校验、分配和指针传递；C/C++ 层在当前 CUDA stream 上启动自写 `maxpool2d_forward_native` 和 `maxpool2d_backward_native`。池化不使用 cuBLAS，卷积仍由同一个 DLL 调度自写 im2col/col2im 和 cuBLAS GEMM。

## 实验条件

- 固定 `seed=0`、FP32、相同输入 fixture、相同 CUDA stream。
- 每个后端每个阶段预热 10 次，采样 3 组、每组 50 次，共 150 个样本。
- 场景为 P3-0-0、P3-0-1、P3-0-2、P3-1-0、P3-1-1、P3-1-2。
- `combined` 包含池化前向和反向；`transfer_inclusive` 还包含输入复制、节点构造和输出复制。
- CuPy 和原生路径的 12 组正确性检查全部通过，参考为独立 NumPy/FP64 结果。

## 组合计时

单位为毫秒，数值越小越快。

| 场景 | CuPy | 原生 C/C++ 调度 | 原生相对 CuPy |
|---|---:|---:|---:|
| P3-0-0 | 0.695574 | 0.089959 | 7.73 倍 |
| P3-0-1 | 0.740475 | 0.093990 | 7.88 倍 |
| P3-0-2 | 1.260230 | 0.121560 | 10.37 倍 |
| P3-1-0 | 0.635981 | 0.097090 | 6.55 倍 |
| P3-1-1 | 0.659676 | 0.107103 | 6.16 倍 |
| P3-1-2 | 1.220118 | 0.100568 | 12.13 倍 |

## 结论和限制

在本次六个固定池化场景中，原生 C/C++ 调度路径的组合计时和传输包含计时均优于 CuPy。收益来自减少 Python/CuPy 算子封装和中间数组管理，并不代表所有输入规模都具有相同加速比。当前 kernel 使用 FP32、NCHW、无 padding、正整数 stride，最大值相等时选择窗口中首次出现的位置。
