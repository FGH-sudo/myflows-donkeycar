## 直接卷积失败基线

单位均为毫秒；数值来自 `performance-final-004` 的正式结果。`组合` 是前向加反向算子调用，`传输包含` 还包含输入输出传输。

| 场景 | NumPy 组合均值 | CuPy 组合均值 | 直接 CUDA C 组合均值 | CuPy/直接 CUDA C |
| --- | ---: | ---: | ---: | ---: |
| P0 小卷积 | 0.167857 | 0.985715 | 1.313838 | 0.750 |
| P1 中等卷积 | 12.362013 | 0.928843 | 1.412187 | 0.658 |
| P2 图像尺度卷积 | 12.434339 | 0.955794 | 1.474788 | 0.648 |

结论：直接 CUDA C 在三个卷积场景中都慢于 CuPy；P0 的 CPU 计算量很小，NumPy 反而最快。这是第一阶段失败基线，不能代表当前原生 C/C++ 调度实现。

## dX 窗口优化

| 场景 | 优化前前反向 | 优化后前反向 | 加速比 |
| --- | ---: | ---: | ---: |
| P0 | 1.269449 | 1.255871 | 1.011 |
| P1 | 1.719162 | 1.187929 | 1.447 |

Nsight Systems 中 P1 的 dX kernel 从 608.337 us 降至 84.661 us，约 7.19 倍；完整算子调用还包含 dW、db、封装和同步开销。

## 正确性

正确性使用独立 FP64 参考实现，联合容差为 `abs(error) <= 1e-4 + 1e-3 * abs(reference)`，相对误差分母为 `max(abs(reference), 1e-6)`。卷积覆盖 Y、dX、dW、db；池化覆盖 Y、dX、负数、tie、重叠窗口、非连续输入和非均匀 dy。

| 检查项 | 结果 |
| --- | --- |
| 卷积 T0-T4 | NumPy、CuPy、当前原生 CUDA 均通过 |
| 池化 T5-T6 | CuPy、当前原生 CUDA 均通过 |
| 小 CNN 100 步 | CuPy 与当前原生 CUDA 均达到 100% 小样本准确率 |
| 图计算与共享参数 | 通过 |
