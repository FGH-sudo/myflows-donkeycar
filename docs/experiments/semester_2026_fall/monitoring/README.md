# 课程任务二：训练监控与冻结反向瓶颈

在 RTX 4060 Laptop 单卡上，冻结前三个阶段的 ResNet18 仍把首层卷积送入反向计算。按梯度需求截断这条路径后，120×160 输入的反向中位耗时从 8.45 降至 4.01 ms，含读取的单步中位耗时从 21.11 降至 14.97 ms。三次重复的前后数据、离散度及 224×224 结果见[冻结对照](freeze-001/report.md)。

## 采集与完整训练

训练入口记录单调时钟、Unix 时间、阶段耗时和 CuPy 池采样峰值。独立进程每 0.5 s 读取 GPU 和主机资源。控制台任务由外部采样器写同一格式。TensorBoard 按已落盘的数据生成曲线。配置、逐行记录、时钟对齐、字段单位及缺测原因详见[监控格式](../../../monitoring_format.md)。

完整训练取 2,000 条真实道路样本，其中 1,800 条训练、200 条验证，batch 2，共 3 轮。单进程加载这一组得到 2,700 个 step、270 个分阶段样本和 357 个 GPU 样本。GPU 利用率中位数 74%，温度中位数 65 °C。设备采样峰值为 4,752.38 MiB，CuPy 的已用采样峰值为 1,356.28 MiB。每步含读取的中位耗时为 46.12 ms。全部 12 项的趋势、中位数、P95、最大值与复现命令见[完整训练报告](trends-001/report.md)。

![三轮训练的 12 项指标](trends-001/trends.png)

预取使用 2 个 loader Worker 时，本次运行的数据读取占比从 16.86% 降至 2.08%，稳态总样本吞吐从 37.94 升至 43.04 samples/s。两组每轮的训练 loss、验证 loss、角度 MAE 相同。单进程组的首轮读取时间明显高于后两轮，结果同时受文件缓存影响。

## 定位与复测

1. `--nvtx-nodes --profile-steps 5:9` 捕获真实训练。冻结前三段后，旧代码仍在每个捕获步调用首个卷积的 backward。每步有 494 个 kernel。超出 0.1 ms 的设备空闲区间按 CPU range 分成 792 个带 step、阶段与源码行号的片段。[改动前时间线](timeline-001/report.md)
2. 在 MyFlows 提交 `0e642cf` 中，`core/graph.py` 的 Graph.backward 清零全部梯度并遍历全部节点，`ops/convolution.py` 的 Conv2D_Op.backward 随后计算 dW。源码位置由捕获目录的 workload/nvtx_map.json 固定到该次版本。
3. `e49d4e3` 为重用的计算图缓存梯度需求。冻结和解冻会重新分析。原生、CuPy、NumPy、深度卷积、Linear 与 BN 都按需要计算父梯度。dX 单独需要时，原生实现在每张图上按转置视图读取 NCHW 梯度。Grad-CAM 可以单独保留特征梯度。
4. 同步边界、样本、初值、后端和监控频率一致的 60 次 A/B 训练覆盖两种输入和五档冻结级别。冻结 3 / 4 段时，120×160 的配对反向时间中位降幅为 58.4% / 77.6%。40 个数值案例覆盖 2,012 组可训练参数，未冻结梯度与一步 Adam 后的张量字节相同，冻结指纹保持一致。
5. 相同步段复测时，每步 kernel 数降至 373，五步内反向区间的 CPU 墙钟合计从 42.302 降至 20.047 ms。两次采集的数据读取区间分别为 50.390 与 82.181 ms，因此训练速度采用上一步的交替计时。[改动后时间线](timeline-freeze-after-001/report.md)

![改动后实际捕获的 step、阶段和 GPU 活动](timeline-freeze-after-001/timeline.png)
