## 误差与速度的来源

TF32 与 FP16 的尾数都是 10 位，各 batch ReLU 输入的相对误差中位数约 1.7×10⁻³；BF16 只有 7 位尾数，约 1.4×10⁻²。每个 batch 中 TF32/FP16 约有 500 个、BF16 约有 4,000 个 ReLU 输入与 FP64 参照异号，表中的梯度误差主要来自这些门控变化，而不是 FP32 累加。逐 batch 的异号数量和 ReLU 误差在 gradients.json。

三个实验后端在卷积中走 CuPy 的通用 im2col 与 NCHW 转置，只把 GEMM 换成指定精度的 cublasGemmEx，没有接入原生卷积调度器的融合尾处理；FP16/BF16 还要多一次 FP32→16 位打包。因此表中步时较慢主要来自卷积路径不同，不能直接归因于 GEMM 精度。另外，Ada 架构白皮书列出的 GeForce RTX 4090 峰值中，TF32 Tensor 与 FP32 非 Tensor 相同，FP16（FP32 累加）为其 2 倍，本机同属 GeForce Ada，TF32 不提供额外的乘加吞吐。这些后端只作对照，不作为默认值。

逐步训练文件、配置、检查点及其来源在各后端的 seed 子目录。
